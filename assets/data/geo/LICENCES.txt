Fonds de carte des diagrammes « Cartes » (carte colorée par zones, carte des migrations)
=====================================================================================

Ces fichiers sont produits par scripts/build-geo-maps.js à partir des sources ci-dessous, téléchargées telles
quelles. Les tracés ont seulement été simplifiés (topojson-simplify) et quantifiés ; aucun contour n'a été
dessiné à la main. Les noms des zones sont en français (traductions ajoutées dans le script) ; les codes
d'origine (INSEE, NUTS, ISO 3166) sont gardés pour relier les lieux de l'application.
Chaque carte dessinée rappelle sa source en petit, en bas à droite (« Fond : … »), comme le demandent les licences.

3. eu-nuts1.json, eu-nuts2.json, be-provinces.json, be-regions.json, ch-cantons.json, ch-regions.json
----------------------------------------------------------------------------------------------------
Source : Eurostat GISCO, nomenclature NUTS version 2024 (régions NUTS 1, 2 et 3), échelles 1:10 000 000 et
1:3 000 000, servie en TopoJSON par Eurostat sur https://github.com/eurostat/Nuts2json (pub/v2/2024/4326/…).
Mention obligatoire, à montrer sur la carte : « © EuroGeographics for the administrative boundaries »
(sur les cartes de l'app : « Fond : © EuroGeographics (Eurostat GISCO) »).
Conditions : https://ec.europa.eu/eurostat/web/gisco/geodata/administrative-units — réutilisation autorisée
à condition de citer la source ; les conditions d'Eurostat GISCO réservent certains jeux de limites
administratives à un usage non commercial : l'application étant libre et gratuite (AGPL), cet usage est couvert ;
à revoir si LCNDA devait un jour être vendue.
Le code de Nuts2json est sous licence EUPL 1.2 (le code n'est pas repris, seulement les données).
Belgique : provinces = NUTS 2 (BE10…BE35), régions = NUTS 1 fondues depuis les provinces.
Suisse : cantons = NUTS 3 (CH011…CH070), grandes régions = NUTS 2. Noms français ajoutés dans le script.

5. fr-communes.json.gz, be-communes.json.gz, ch-communes.json.gz, lu-communes.json.gz — niveau « Communes (villes) »
------------------------------------------------------------------------------------------------------------------
Produits par scripts/build-geo-communes.js. Fichiers JSON compressés en gzip (l'application les décompresse elle-même),
chargés seulement quand on choisit le niveau « Communes (villes) ». Tracés fortement simplifiés (topojson-simplify),
limites communes partagées (TopoJSON) ; aucun tracé n'a été dessiné à la main.

France (fr-communes.json.gz, 34 868 communes, outre-mer compris) :
  Tracés : IGN, Admin Express COG (édition 2018), fichier communes-avec-outre-mer.geojson de
  https://github.com/gregoiredavid/france-geojson (même source que les départements, point 2).
  Communes au 1er janvier 2025 : INSEE, Code officiel géographique 2025, par le paquet npm
  @etalab/decoupage-administratif 6.0.0 (data/communes.json ; code sous licence MIT, données INSEE).
  Les tracés 2018 des communes fusionnées depuis sont réunis (topojson merge) en commune nouvelle ; les anciennes
  communes (déléguées, associées) et les arrondissements de Paris, Lyon et Marseille sont gardés comme « autres noms »
  et « autres codes ». 85 anciens codes sans commune déléguée sont rattachés à la commune voisine issue d'une fusion.
  Licence : Licence Ouverte / Open Licence (Etalab), https://www.etalab.gouv.fr/licence-ouverte-open-licence
  Mention à afficher : « Source : IGN – Admin Express COG 2018 ; INSEE – COG 2025 »
  (sur la carte : « Fond : IGN Admin Express, INSEE COG 2025 (Licence Ouverte) »).

Belgique (be-communes.json.gz, 565 communes de 2025) :
  Tracés : IGN-NGI (Institut géographique national), communes 2025, via l'Open Data Wallonie-Bruxelles, licence
  ouverte de l'IGN ; repris du fichier de référence de LCNDA data/reference/geo-be.sqlite.gz
  (scripts/build-reference-europe.php). Codes INS (REFNIS).
  Noms français et néerlandais : Statbel (Direction générale Statistique), CC BY 4.0, par le paquet npm
  be-legal-data 0.2.0 (data/municipalities.json, © Statbel, CC BY 4.0 ; https://creativecommons.org/licenses/by/4.0/).
  Anciennes communes et sections (autres noms) : GeoNames (https://www.geonames.org), CC BY 4.0.
  Mention à afficher : « IGN-NGI ; Statbel (CC BY 4.0) » (sur la carte : « Fond : IGN-NGI, Statbel (CC BY 4.0) »).

Suisse (ch-communes.json.gz, 2 110 communes de 2026) :
  Tracés : swissBOUNDARIES3D 2026, © swisstopo (Office fédéral de topographie), conditions Opendata BY
  (« utilisation libre, indication de la source obligatoire »), https://www.swisstopo.admin.ch/fr/conditions-d-utilisation-des-geodonnees-ogd ;
  repris du fichier de référence de LCNDA data/reference/geo-ch.sqlite.gz. Numéros OFS des communes.
  Hameaux et anciennes communes (autres noms) : GeoNames, CC BY 4.0. Quelques noms français ajoutés dans le script
  (Berne, Bâle, Lucerne…).
  Mention à afficher : « © swisstopo » (sur la carte : « Fond : © swisstopo (Opendata BY) »).

Luxembourg (lu-communes.json.gz, 100 communes) :
  Tracés : Administration du cadastre et de la topographie (ACT), limites communales, data.public.lu, licence CC0 ;
  repris du fichier de référence de LCNDA data/reference/geo-lu.sqlite.gz. Codes LAU.
  Noms allemands et luxembourgeois, sections (autres noms) : GeoNames, CC BY 4.0.
  Mention (facultative pour CC0) : « ACT Luxembourg » (sur la carte : « Fond : ACT Luxembourg (CC0) »).

GeoNames (autres noms des communes belges, suisses et luxembourgeoises) : © GeoNames, Creative Commons Attribution
4.0 (https://creativecommons.org/licenses/by/4.0/) ; seulement utilisés pour retrouver un lieu, jamais affichés seuls.
Province (Belgique) ou canton (Suisse, Luxembourg) de chaque commune : d'après ces mêmes lieux GeoNames, sinon
d'après les fonds be-provinces, ch-cantons et lu-cantons (point 3 et 4).

Encart de l'Île-de-France : fr-departements.json et fr-regions.json gardent des tracés plus fins dans la boîte
1,4° E – 3,6° E, 48,1° N – 49,25° N (scripts/build-geo-maps.js, IDF_BOOST), pour rester lisibles une fois agrandis.
