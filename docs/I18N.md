# 🌐 Traduire l’app (mode d’emploi)

LCNDA est écrite en français. Le français est **la langue de référence** : il ne change jamais à l’écran.
Quinze autres langues sont proposées : anglais (`en`), espagnol (`es`), allemand (`de`), italien (`it`),
portugais (`pt`), polonais (`pl`), néerlandais (`nl`), tchèque (`cs`), suédois (`sv`), danois (`da`), et, en cours de traduction,
slovaque (`sk`), norvégien bokmål (`nb`), roumain (`ro`), finnois (`fi`) et hongrois (`hu`). Leurs traductions sont faites par une IA : un bandeau
le dit dans chaque langue, avec « Signaler une erreur » (il ouvre « 🐞 Signaler un problème », pré-rempli « traduction »).

## Ce qu’il y a

| Fichier | Rôle |
|---|---|
| `assets/js/app-i18n.js` | `window.LCNDA_I18N` (aussi `require()` dans Node) : `t()`, `plural()`, `fmtNumber()`, `fmtDate()`, `fmtTime()`, `setLang()`, le bandeau, le filet de la page. Chargé tout de suite après `app-journal.js`, sans `defer`. |
| `assets/i18n/src/nord/*.tsv` | Les traductions en tchèque, suédois, danois (`fr ¦ cs ¦ sv ¦ da`), un fichier par zone, même clé : voir « Ajouter une langue ». |
| `assets/i18n/src/nord2/*.tsv` | Les traductions en slovaque et norvégien bokmål (`fr ¦ sk ¦ nb`), un fichier par zone, même clé. |
| `assets/i18n/src/nord3/*.tsv` | Les traductions en roumain (`fr ¦ ro`), un fichier par zone, même clé. |
| `assets/i18n/src/nord4/*.tsv` | Les traductions en finnois et en hongrois (`fr ¦ fi ¦ hu`), un fichier par zone, même clé. |
| `scripts/i18n-todo.js` | Ce qui reste à traduire dans une langue, zone par zone (avec l’anglais et l’allemand en aide, plus le tchèque pour `sk`, le danois pour `nb`, l’italien pour `ro` et le suédois pour `fi`). |
| `assets/i18n/src/*.tsv` | **Les sources** des traductions, une zone de l’app par fichier (`composants`, `cadre`, `colonnes`, `reglages`, `premier`, `serveur`…). On écrit ici. |
| `assets/i18n/<code>.json` | Fabriqués par `node scripts/i18n-build.js` : ne pas les modifier à la main. |
| `lib/i18n.php` | Le même dictionnaire côté serveur : `i18n_t()`, `<html lang>`, le dictionnaire écrit dans la page (cookie `lcnda_lang`), le message `error` de `json_response()` traduit (en-tête `X-LCNDA-Lang` envoyé par `api()`). |
| `scripts/i18n-extract.js` | Les textes français encore écrits en dur (et ceux de `t()` absents d’une langue). |
| `scripts/i18n-check.js` | Clés manquantes, variables `{x}` différentes, pluriels incomplets, symbole de tête perdu, longueurs suspectes. |
| `scripts/i18n-remaining.js` | Reconnaît un texte resté en français à l’écran (pour les tests). |
| `docs/i18n-glossaire.md` | Les mots de la généalogie et de l’app dans toutes les langues (sections à part pour cs / sv / da, sk / nb, ro et fi / hu) : **à suivre** pour toute nouvelle traduction. |
| `tests/test-i18n.js` | Le test (et `tests/test-i18n-nord.js` pour cs / sv / da, `tests/test-i18n-nord2.js` pour sk / nb, `tests/test-i18n-nord3.js` pour ro, `tests/test-i18n-nord4.js` pour fi / hu). |

## La clé, c’est le texte français

```js
const {t, plural} = window.LCNDA_I18N;            // dans un nouveau fichier
const i18n = (s, v) => (window.LCNDA_I18N ? window.LCNDA_I18N.t(s, v) : s); // dans un fichier existant (pas de nom « t » qui se cache)

t('Enregistrer')                                  // « Save », « Guardar »… ; en français : « Enregistrer »
t('Réglages gardés sous « {name} ».', {name})     // les variables entre accolades, les mêmes dans toutes les langues
t('Voir les {n} suivants ↓', {n: 40})             // un nombre est écrit selon la langue (1 234 / 1,234 / 1.234)
t('Fiche', {ctx: 'onglet'})                       // clé « onglet|Fiche » quand un même mot se traduit autrement ; repli sur « Fiche »
plural(3, 'personne')                             // « 3 personnes », « 3 people », « 3 osoby », « 5 osób » (Intl.PluralRules)
```

- **Repli** : une traduction absente → le texte français, jamais une clé ni un vide.
- **En français, rien ne bouge** : `t()` rend le texte tel quel ; `plural()` est celui d’avant (0 et 1 au singulier) ;
  le filet de la page ne s’allume pas.
- **Un texte avec une partie variable s’écrit en entier** dans `t()` (`t('Réglage changé : « {what} »', {what})`),
  jamais en morceaux (`'Réglage changé : « ' + x + ' »'`) : chaque langue range les mots à sa façon.
- Le HTML reste dans le code : `t('<b>{what} à corriger</b> avant d’enregistrer.', {what})` est permis quand la phrase
  entière en a besoin ; les variables qu’on y met sont déjà échappées (`esc(q)`).
- Les **données** ne se traduisent jamais (noms, notes, lieux, titres choisis par la personne). Une zone qui montre des
  données et risque de ressembler à un texte de l’app : `data-i18n-off`.

## Textes du serveur

- Un message `error` connu (exactement une clé) est traduit tout seul par `json_response()` : on écrit le français
  dans `throw new RuntimeException('…')` comme avant et on ajoute la ligne dans `assets/i18n/src/serveur.tsv`.
- Un message avec une partie variable, ou un texte calculé renvoyé au navigateur (titres et détails du ✅ Contrôle de la
  base, « pourquoi » de « Que manque-t-il ? », indices des murs de brique, lignes de « Ma semaine »…) : `i18n_t('… {x} …',
  ['x' => $x])`, phrase entière, une phrase par sexe quand le français accorde. En français, la phrase reste mot pour mot.
- Jamais pour ce qui est enregistré ou comparé : clés, empreintes (`fp` du Contrôle calculée sur le français),
  `what` de « Que manque-t-il ? » (recherches FranceArchives), noms des services d’archives (ils retrouvent les
  dépouillements), badges de « Ma semaine » dont le navigateur tire la couleur, en-têtes CSV, GEDCOM.
- Un résultat gardé en cache contient des phrases : un fichier par langue (`cache/controle.json` pour le français,
  `cache/controle-de.json`…). Test : `tests/test-i18n-serveur.js`.

## Le filet de la page

Dans une autre langue que le français, `app-i18n.js` relit aussi la page (textes, `title`, `placeholder`,
`aria-label`, `alt`) et remplace un texte qui est exactement une clé connue :

- avec ou sans symbole devant (« ＋ Ajouter… », « 🐾 Animaux », « ✓ Compris ») et « … », « : », « ▾ » au bout ;
- les modèles à variable (`Infos {x}`, `{x} (Outil de modification)`) : la variable est traduite aussi, sinon le modèle
  n’est pas pris (pas de phrase à moitié traduite), sauf les variables libres (`{name}`, `{q}`, `{n}`…) ;
- les textes « a · b » morceau par morceau.

Le filet sert pour le HTML écrit en dur (index.php, gabarits) ; **tout nouveau texte passe par `t()`**.
Zones jamais retouchées : `[data-i18n-off]`, champs de saisie, `contenteditable`, `script`, `style`, `code`.

## Règle pour tout nouvel outil

1. Écrire les textes en français dans le code avec `t('…')` (ou `i18n('…')`), en suivant les règles validées (K3, K11…).
2. Ajouter les lignes dans `assets/i18n/src/<zone>.tsv` (7 traductions, glossaire), puis `node scripts/i18n-build.js`.
3. `node scripts/i18n-check.js` doit dire 0 erreur ; `node scripts/i18n-extract.js mon-fichier.js --missing de` ne doit rien
   lister de visible.
4. Monter `?v=` du fichier JS dans `index.php` ; les `.json` de langue ont leur numéro dans `app-i18n.js` (`VERSION`).

## Format d’un fichier .tsv

```
fr ¦ en ¦ es ¦ de ¦ it ¦ pt ¦ pl ¦ nl
Enregistrer ¦ Save ¦ Guardar ¦ Speichern ¦ Salva ¦ Guardar ¦ Zapisz ¦ Opslaan
onglet|Fiche ¦ Record ¦ Ficha ¦ Eintrag ¦ Scheda ¦ Ficha ¦ Karta ¦ Profiel
=personne ¦ person|people ¦ persona|personas ¦ Person|Personen ¦ persona|persone ¦ pessoa|pessoas ¦ osoba|osoby|osób ¦ persoon|personen
# un commentaire
```

Séparateur : une tabulation, ou « ¦ » entouré d’espaces. `=mot` = un pluriel (`one|other`, et `one|few|many` en polonais,
en tchèque et en slovaque : 1 | 2 à 4 | 5 et plus ; `one|few|other` en roumain : 1 | 0 et 2 à 19 | 20 et plus, avec « de » :
`persoană|persoane|de persoane` ; `one|other` en finnois et en hongrois, où le nom reste au singulier après un nombre :
`személy|személy`).

## Ajouter une langue

1. `assets/js/app-i18n.js` : une ligne dans `LANGS` (code, nom dans sa langue, drapeau, locale Intl) ; monter `VERSION`.
   Le menu des langues (Apparence, premier lancement) la montre tout seul.
2. `lib/i18n.php` : le code dans `I18N_LANGS`.
3. `scripts/i18n-build.js` : le code dans `NEW_LANGS` (et ses formes de pluriel dans `FORMS` si ce n’est pas `one|other`),
   son nom dans `NAMES` ; `scripts/build-faq-i18n.js` : le code dans `NEW_LANGS`.
4. Les traductions vont dans **des fichiers à part**, un par zone, dans un sous-dossier de `assets/i18n/src/` :
   `nord/<zone>.tsv` (1re ligne `fr ¦ cs ¦ sv ¦ da`), `nord2/<zone>.tsv` (1re ligne `fr ¦ sk ¦ nb`), `nord3/<zone>.tsv`
   (1re ligne `fr ¦ ro`), `nord4/<zone>.tsv` (1re ligne `fr ¦ fi ¦ hu`). Tout sous-dossier de `src/`
   qui a des `.tsv` est lu ; la 1re ligne de chaque fichier dit ses langues (pour une nouvelle langue : un nouveau dossier, ou une
   colonne de plus dans un dossier existant). On ne touche pas aux `.tsv` des 7 premières langues. Le script fusionne clé par clé
   (la même clé dans `nord/` et `nord2/` n’est pas un doublon : chacun a ses langues).
5. Tant qu’une langue de `NEW_LANGS` n’est pas finie, une clé absente est un **avertissement compté**
   (« cs : N textes encore sans traduction », repli sur le français) ; une variable `{x}` différente, un pluriel incomplet ou un
   symbole de tête perdu restent des **erreurs**. Quand elle est finie : `node scripts/i18n-check.js --strict-new` (0 erreur),
   puis passer son code de `NEW_LANGS` à `CORE`.

### Traduire une zone en tchèque, suédois, danois (méthode pour plusieurs personnes ou assistants en même temps)

(Pour le slovaque et le norvégien : voir la section suivante, même méthode avec `nord2/`.)

1. `node scripts/i18n-todo.js cs all` : ce qui reste, zone par zone. Prendre **une zone** (personne d’autre ne la prend).
2. `node scripts/i18n-todo.js cs,sv,da <zone>` : les clés de `<zone>.tsv` sans traduction (clé ⇥ anglais ⇥ allemand, en aide ;
   `--skeleton` : lignes prêtes à remplir).
3. Écrire **seulement** `assets/i18n/src/nord/<zone>.tsv` (le créer avec la 1re ligne `fr ¦ cs ¦ sv ¦ da`) : la clé recopiée telle
   quelle (avec `ctx|` et `=` pour un pluriel), puis les 3 traductions. Pluriel tchèque en 3 formes (`osoba|osoby|osob`), suédois
   et danois en 2. Suivre le glossaire (section « Langues ajoutées ensuite »), le tutoiement, les guillemets de chaque langue.
4. `node scripts/i18n-build.js && node scripts/i18n-check.js` : 0 erreur ; `node scripts/i18n-todo.js cs,sv,da <zone>` : vide.
5. Une clé déjà traduite dans une autre zone compte comme faite partout (pas besoin de la répéter).
6. La FAQ : même principe que les autres langues, `assets/i18n/faq/src/cs/*.tsv` (`node scripts/build-faq-i18n.js --todo
   <dossier> --lang cs` pour les paquets), puis `node scripts/build-faq-i18n.js`.
7. Test : `node tests/test-i18n-nord.js`.

### Traduire une zone en slovaque et norvégien bokmål (sk, nb)

Socle fait : les 7 zones `cadre`, `composants`, `colonnes`, `premier`, `touches`, `reglages`, `faq` (le cadre de l’app, les
fenêtres communes, la colonne de gauche, le premier lancement, les touches, les pages des Réglages, les textes de la FAQ).
Le reste revient au français en attendant.

1. `node scripts/i18n-todo.js sk,nb all` : ce qui reste, zone par zone (les plus petites d’abord). Prendre **une zone** que
   personne d’autre ne prend (une zone à la fois par assistant ; jamais deux assistants sur le même fichier).
2. `node scripts/i18n-todo.js sk,nb <zone>` : clé ⇥ anglais ⇥ allemand ⇥ **tchèque** ⇥ **danois** ⇥ langues qui manquent.
   Le tchèque est très proche du slovaque, le danois écrit est très proche du bokmål : s’en servir beaucoup, mais **traduire
   depuis le français** (le sens), puis vérifier les mots propres à chaque langue (sk : *ä, ô, ĺ, ľ, ŕ*, « Uložiť », pas
   « Uložit » ; nb : « Lagre », « Innstillinger », *-er* des pluriels, « datamaskin » et non « computer »). `--skeleton` : lignes
   « clé ¦ ¦ » prêtes à remplir.
3. Écrire **seulement** `assets/i18n/src/nord2/<zone>.tsv` (le créer avec la 1re ligne `fr ¦ sk ¦ nb`) : la clé recopiée telle
   quelle (avec `ctx|` et `=`), puis les 2 traductions. Pluriel slovaque en 3 formes (`osoba|osoby|osôb` : 1 | 2 à 4 | 5 et plus),
   norvégien en 2 (`person|personer`). Mêmes variables `{x}` que le français, même symbole de tête (＋ ↶ ⤒ ✓ ⚠️…).
   Tutoiement (sk *ty*, impératif « Vyber », « Klikni » ; nb *du*, impératif « Velg », « Klikk »), guillemets sk „…“, nb «…».
   Mots : glossaire, section « Langues ajoutées ensuite : slovaque (sk), norvégien bokmål (nb) ».
4. `node scripts/i18n-build.js && node scripts/i18n-check.js` : 0 erreur ; `node scripts/i18n-todo.js sk,nb <zone>` : vide.
5. Une clé déjà traduite dans une autre zone compte comme faite partout.
6. La FAQ : `assets/i18n/faq/src/sk/*.tsv` et `…/nb/*.tsv` (vides au départ : repli sur le français) ;
   `node scripts/build-faq-i18n.js --todo <dossier> --lang sk` pour les paquets, puis `node scripts/build-faq-i18n.js`
   (et monter `VERSION` du script avec `FAQ_I18N_V` de heritage-more.js).
7. Test : `node tests/test-i18n-nord2.js` (aussi `I18N_PORT=…` pour choisir le port).
8. Quand une langue est finie : `node scripts/i18n-check.js --strict-new --lang sk` (0 erreur), puis passer son code de
   `NEW_LANGS` à `CORE` dans `scripts/i18n-build.js`.

### Traduire une zone en roumain (ro)

Socle fait : les 11 zones `cadre`, `composants`, `colonnes`, `premier`, `touches`, `reglages`, `faq`, `signaler`, `montage`,
`reste4`, `reste5` (≈ 1 700 textes). Le reste revient au français en attendant ; la FAQ (`assets/i18n/faq/src/ro/`) est vide.

1. `node scripts/i18n-todo.js ro all` : ce qui reste, zone par zone (les plus petites d’abord). Prendre **une zone** que
   personne d’autre ne prend.
2. `node scripts/i18n-todo.js ro <zone>` : clé ⇥ anglais ⇥ allemand ⇥ **italien** (langue romane proche, en aide).
   **Traduire depuis le français** (le sens), avec les diacritiques roumains corrects : *ă, â, î, ș, ț* (ș et ț **avec virgule**
   dessous, U+0219 / U+021B, jamais ş / ţ avec cédille).
3. Écrire **seulement** `assets/i18n/src/nord3/<zone>.tsv` (1re ligne `fr ¦ ro`). Pluriel en 3 formes
   (`persoană|persoane|de persoane` : 1 | 0 et 2 à 19 | 20 et plus). Mêmes variables `{x}`, même symbole de tête.
   Tutoiement (*tu*, impératif 2e personne du singulier : « Alege », « Fă clic », « Adaugă » ; boutons à l’impératif :
   « Salvează », « Șterge »), guillemets „…”. Mots : glossaire, section « Langue ajoutée ensuite : roumain (ro) ».
4. `node scripts/i18n-build.js && node scripts/i18n-check.js` : 0 erreur ; `node scripts/i18n-todo.js ro <zone>` : vide.
5. Test : `node tests/test-i18n-nord3.js` (le serveur suit la règle roumaine des pluriels dans `i18n_t()`).

### Traduire une zone en finnois (fi) et en hongrois (hu)

Socle fait : les mêmes 11 zones que le roumain (`cadre`, `composants`, `colonnes`, `premier`, `touches`, `reglages`, `faq`,
`signaler`, `montage`, `reste4`, `reste5`, ≈ 1 700 textes). Le reste revient au français en attendant ; la FAQ
(`assets/i18n/faq/src/fi/`, `…/hu/`) est vide.

1. `node scripts/i18n-todo.js fi all` (ou `hu all`) : ce qui reste, zone par zone. Prendre **une zone** que personne d’autre ne prend.
2. `node scripts/i18n-todo.js fi,hu <zone>` : clé ⇥ anglais ⇥ allemand ⇥ **suédois** (aide pour le finnois ; l’allemand sert
   d’aide pour le hongrois). **Traduire depuis le français** (le sens).
3. Écrire **seulement** `assets/i18n/src/nord4/<zone>.tsv` (1re ligne `fr ¦ fi ¦ hu`). Pluriels `one|other` (`henkilö|henkilöä` ;
   hongrois : singulier après un nombre, `személy|személy`). Mêmes variables `{x}`, même symbole de tête. Tutoiement (fi : *sinä*
   sous-entendu, « Valitse », « Tallenna » ; hu : *te*, « Válaszd ki », boutons « Mentés », « Törlés »). Guillemets ”…” (fi),
   „…” (hu). Mots : glossaire, section « Langues ajoutées ensuite : finnois (fi) et hongrois (hu) ».
4. `node scripts/i18n-build.js && node scripts/i18n-check.js` : 0 erreur ; `node scripts/i18n-todo.js fi,hu <zone>` : vide.
5. Test : `node tests/test-i18n-nord4.js`.

## Ce qui n’est pas traduit (pour l’instant)

La fiche d’une personne en entier, les outils (éditeurs, jeux, Studio son…), la FAQ, les dictionnaires et données de
référence (métiers, prénoms, calendriers), la lecture des dates C4 (« 7 mai 1925 » reste compris à la française).
`node scripts/i18n-extract.js assets/js --summary --missing en` donne le reste, fichier par fichier.

## La FAQ (zone « faq »)

La FAQ (≈ 800 questions, ≈ 450 000 lettres) n’entre pas dans les fichiers de langue ordinaires : ils sont lus à chaque
ouverture de l’app, la FAQ seulement quand on en a besoin.

| Fichier | Rôle |
|---|---|
| `assets/js/heritage-more.js` (`const FAQ = [ … ]`) | **La FAQ française, la référence** : on y écrit toujours en premier. |
| `assets/i18n/faq/src/<code>/*.tsv` | Les traductions, une ligne par question : `repère.empreinte` ⇥ question ⇥ réponse (tabulations). |
| `assets/i18n/faq/<code>.json` | Fabriqués par `node scripts/build-faq-i18n.js` (ne pas modifier à la main) ; lus par la page FAQ, la recherche, la fenêtre « ❓ Aide (FAQ) » et les bulles « En savoir plus (FAQ) → ». |
| `assets/i18n/src/faq.tsv` | Les textes ordinaires de la zone : thèmes (`faq|Fiches`…), case de recherche, messages, page « FAQ / tuto ». |
| `scripts/build-faq-i18n.js` | Fabrique les `.json` ; `--status` (ce qui manque, langue par langue) ; `--todo <dossier>` (les questions à traduire, par paquets). |

- **Le repère d’une question** est tiré de sa question française (FNV-1a, le même calcul dans `faqId` de heritage-more.js et dans
  le script) ; **l’empreinte** est tirée de sa réponse française. Réponse française changée → l’empreinte ne correspond plus :
  la question reste traduite, la réponse revient au français jusqu’à ce qu’on la retraduise (`--status` la liste « à revoir »).
  Question française changée → la ligne n’est plus reconnue (« lignes en trop ») : la retraduire avec son nouveau repère.
- **Repli** : une question pas encore traduite s’affiche en français (avec `lang="fr"`), jamais un vide.
- **Les liens** `data-help-faq="…"`, `UI.openFaq('…')`, `ext.faqPopup('…')` citent des mots ou des questions **en français** :
  la recherche cherche dans la langue choisie **et** dans le français, et une question française citée en entier passe devant
  tout (elle s’affiche alors traduite dans la case). On continue donc d’écrire ces liens en français.
- **La recherche** : petits mots à ignorer, racines et quelques synonymes propres à chaque langue (`FAQ_STOP_L`, `FAQ_STEM`,
  `FAQ_SYN_L`) ; les traductions sont lues en avance (sans bloquer) quelques secondes après l’ouverture de l’app.
- Une touche propre à l’ordinateur s’écrit `{mac:⌃⌘Espace|pc:⊞ + .}` dans la traduction.
- Après une nouvelle question ou une réponse changée : la traduire dans les 7 langues, `node scripts/build-faq-i18n.js`,
  monter `FAQ_I18N_V` (heritage-more.js) avec `VERSION` (le script), puis `node tests/test-i18n-faq.js`.
- La FAQ de la page de présentation (`faq-data.js`, `scripts/build-faq-data.js`) reste en français.
